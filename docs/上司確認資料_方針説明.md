## 1. 費用：なぜ月¥150で足りるのか

### 1-1. 費用の内訳

```
月額固定費
  ドメイン（gooddaymate.jp）  ¥150/月
  ホスティング（サーバー代）   ¥0/月  ← Cloudflare Pages 無料プラン
  SSL（https化）              ¥0/月  ← 自動付与
  予約システム               ¥0/月  ← テマイラズ既存契約内
  ─────────────────────────────────
  合計                        ¥150/月
```

### 1-2. 「無料で大丈夫か」への回答

一般的に「無料＝貧弱」と思われがちですが、今回使用する **Cloudflare Pages** は構造が異なります。

```
【よくある格安サーバー】                【Cloudflare Pages】

 ¥300/月のレンタルサーバー              無料
 └── 帯域：月10GB上限                 └── 帯域：無制限
 └── アクセス集中で重くなる           └── 世界180拠点から配信
 └── 日本のみに1台のサーバー          └── アクセス集中に自動対応
```

Cloudflare はインターネットインフラ企業であり、
**Booking.com・Airbnb・LINE・Discord** も同社のサービスを利用しています。
「無料プランでも商用利用OK」と規約で明示されており、
2施設規模では性能上の上限に達することは現実的にありません。

### 1-3. アクセス数と費用の関係

| 月間訪問者数 | 費用 | 判定 |
|------------|------|------|
| 〜1,000人（開設直後） | **¥150** | ✅ |
| 〜10,000人（軌道に乗った後） | **¥150** | ✅ |
| 〜100,000人（かなり人気） | **¥150** | ✅ |

### 1-4. 投資対効果

```
現在のOTA手数料負担（推定）
  月間売上 × 15% = OTA手数料

例：月20泊 × 平均¥40,000
  → 売上 ¥800,000 × 15% = 月¥120,000 をOTAに支払い

自社サイト経由に5泊/月 移行できた場合
  削減額：¥200,000 × 15% = 月¥30,000 の節約
  サイト維持費 ¥150/月 と比較
  → 投資回収率：20,000倍
```

## 2. 予約システム：テマイラズで完結する理由

### 2-1. 現在の予約管理フロー（テマイラズ使用中）

```
現在の構成

  Booking.com ─┐
  Airbnb      ─┤─→【テマイラズ】← カレンダーを一元管理
  その他OTA   ─┘          ↑
                           在庫をリアルタイム同期
                           ダブルブッキングを防止
```

### 2-2. テマイラズに「直接予約機能」が標準搭載されている

テマイラズには、**自社サイトから直接予約を受け付けるウィジェット機能**が含まれています。
これは追加費用なし、既存の契約内で利用可能です。

```
導入後の構成

  gooddaymate.jp（自社サイト）
       ↓「予約する」ボタン
  【テマイラズ 予約ウィジェット】← 既存サービスの機能を使うだけ
       ↓ リアルタイム自動同期
  【テマイラズ】← 在庫の司令塔は変わらない
       ↓
  Booking.com・Airbnb・その他OTA

ダブルブッキングが起きない理由：
  在庫を管理しているのは「テマイラズ」1か所のみ。
  どこから予約が入っても、テマイラズが在庫を即時更新するため
  物理的にダブルブッキングが発生しない。
```

**作業量**：テマイラズの管理画面からウィジェットコードをコピーして
　　　　　サイトに貼り付けるだけ。エンジニア不要。

### 2-3. 三択の比較：テマイラズ活用 vs Beds24 vs 自社開発

| 比較項目 | テマイラズ活用（推奨） | Beds24 導入 | 自社開発 |
|---------|---------------------|------------|---------|
| 追加費用 | **¥0** | ¥1,500〜3,000/月 | 開発費100〜500万円 |
| 導入期間 | **数日** | 1〜2週間 | 4〜8ヶ月 |
| OTA連携 | **完璧（既存のまま）** | 要設定 | 要開発 |
| ダブルブッキングリスク | **ゼロ（構造上）** | 低（要設定） | 要実装 |
| 障害対応 | テマイラズが対応 | Beds24が対応 | 自社対応 |
| 将来の変更 | 容易 | 容易 | 困難 |
| **総合評価** | **◎** | ○ | △ |

**自社開発を選ぶべき条件（現状は該当しない）**

```
以下をすべて満たす場合のみ自社開発が有利：
  □ 月間予約数が 300件以上ある
  □ 専任エンジニアが社内にいる
  □ テマイラズ・Beds24では実現できない独自要件がある
  □ 開発・保守に年間200〜500万円の予算がある

→ 2施設・スタートアップ段階の現在には当てはまらない
```

## 3. スケーリング：大規模化した場合の方針

### 3-1. 段階的な移行計画

```
現在                    移行コスト    対応できる規模
─────────────────────────────────────────────────
Cloudflare Pages 無料
 ¥150/月                  ¥0      月10万人アクセスまで
         ↓ 必要になったら（目安：施設10棟以上）
Cloudflare Workers 有料
 ¥850/月                  ¥0      月1,000万リクエストまで
         ↓ 更に大規模化（目安：施設50棟以上・自社予約300件/月超）
VPS（自社サーバー）
 ¥3,000〜5,000/月       30分の設定   事実上無制限
```

### 3-2. 移行が「簡単にできる」理由

```
コード（設計図）は GitHub というサービスで管理している
         ↓
Cloudflare・Vercel・VPS はどれも「この設計図を表示するだけ」

移行＝「表示する場所を変える」だけ
  → コードの変更ゼロ
  → 所要時間：30分〜2時間
  → 費用：ゼロ（設定作業のみ）

例：引越しの際に「家具」はそのまま運べる
   変わるのは「住む家（サーバー）」だけ
```

## 4. 今回の方針が最適である根拠

### 4-1. 方針サマリー

```
Phase 1（今〜4月）    ¥150/月
  公式サイト公開
  「予約する」→ 既存OTAへリンク（ダブルブッキングリスクゼロ）
  ブランド認知の確立・Googleへのインデックス開始

Phase 2（4〜5月）    ¥150/月
  アクセス解析でユーザー行動を計測
  写真・テキストを改善
  Instagram連携で認知拡大

Phase 3（5〜6月以降） ¥150/月
  テマイラズの直接予約ウィジェットを接続
  自社予約の受付開始
  OTA手数料の削減スタート
```

| リスク | 評価 | 対策 |
|--------|------|------|
| ダブルブッキング | **低**（テマイラズが一元管理） | テマイラズウィジェット活用 |

| 予約システム障害 | **既存と同じ**（テマイラズ依存は変わらない） | テマイラズのサポート利用 |
